# Вход → расчёт → выход: первый прогон по ТЗ

Ветка test-main. Вход теперь загружается пользователем, а не ограничивается demo.
Первый этап интеграции 1С — **файловый обмен**. Прямое подключение к реальной
конфигурации требует её имени, опубликованного интерфейса и согласования
регистров/отчётов; адрес и учётные данные не угадываются.

## Подготовка файлов

Можно загрузить одну книгу Excel с листами sales, products, suppliers, inventory,
stockouts, in_transit либо несколько файлов с такими именами.
Русские имена листов/файлов: Продажи, Товары, Поставщики, Остатки,
Отсутствие, В пути, Материальная ведомость.
XLSX и XLS: первая строка — заголовки, без объединённых ячеек, формул и итогов.
В старом XLS читаются сохранённые значения ячеек: наличие исходной формулы
надёжно не определяется. Перед выгрузкой пересчитайте книгу и сохраните значения.
CSV/TSV: UTF-8 или Windows-1251, запятая/точка с запятой/табуляция.
JSON: объект с ключами таблиц и массивами строк либо массив для одного файла.
PDF: текстовые таблицы с явными границами и повторяющимися заголовками;
имя файла определяет вид таблицы. Скан/фото не распознаётся как готовые данные.

Обязательны sales, products, suppliers и inventory (или material_statement).
Отсутствие stockouts/in_transit допускается с явными предупреждениями.
Пустой файл с заголовками — явное указание, что событий не было.

| Таблица | Поля |
|---|---|
| sales | date, sku, units; customer_id (уже обезличенный), price, warehouse_id |
| products | sku, name, supplier_id, active; category, unit |
| suppliers | supplier_id, supplier_name, lead_time_days |
| inventory | sku, on_hand; warehouse_id |
| stockouts | sku, start_date, end_date; warehouse_id |
| in_transit | sku, quantity, expected_date; warehouse_id |
| material_statement | sku, on_hand; warehouse_id (конечный остаток из 1С) |

Русские заголовки переводятся детерминированно: Дата, Артикул, Количество,
Обезличенный клиент, Цена, Склад, Наименование, Код поставщика, Поставщик,
Срок поставки, Остаток / Конечный остаток, Дата начала, Дата окончания,
Ожидаемая дата, Категория, Единица, Активен.
Числа с десятичной запятой и даты ДД.ММ.ГГГГ нормализуются.
Артикулы, записанные числом в Excel, нельзя восстановить с потерянными нулями:
храните SKU и коды как текст.

Если переданы два источника остатков (inventory и ведомость), они должны
совпадать после выбора склада; иначе импорт отклоняется.
Если складов несколько, укажите warehouse_id при импорте.
Остатки без склада нельзя смешивать с историей нескольких складов.
Цена сохраняется для аудита; она не меняет формулу потребности в единицах.
Категория и единица сохраняются для отображения/фильтрации.

## LOGISTIQ XLSX

Поддерживается книга с листами `Upload Data`, `Current Snapshot`,
`Expected Results`, `Data Dictionary`: заголовки на третьей строке.
Два последних листа справочные, не используются как результаты расчёта.

- `Upload Data`: `sales_qty` → фактические продажи; `stockout_flag` → дни
  отсутствия. `lost_sales_estimate`, `corrected_demand_qty`, `anomaly_flag`
  не подменяют алгоритм: потерянный спрос и аномалии вычисляются заново.
- `Current Snapshot`: `На складе`, `В пути`, `ETA`, `Lead time` → текущие
  остатки, поставки и срок поставки. Этот явно обозначенный текущий снимок
  имеет приоритет над историческими остатками из `Upload Data`.
- SKU, название, категория и поставщик сверяются между листами. SKU должны
  совпадать; дубли дат/SKU/склада, отрицательные числа, отсутствующий ETA для
  ненулевой поставки и неизвестные колонки входных листов отклоняются.
- Такой снимок не содержит склада: допускается ровно один склад в истории.
- Код поставщика формируется стабильно из имени и срока поставки: в текущем
  контракте срок относится к поставщику, поэтому одно имя с разными сроками
  образует отдельные группы поставки. Об этом выводится предупреждение.
- `unit_cost_kzt` — закупочная стоимость, не цена продажи; она не переносится
  в `sales.price`. Клиенты и цены продаж не выдумываются.
- MOQ, упаковки, backorders, service level, промо и влияние ETA на доступность
  не входят в формулу MVP. Ограничения отображаются в предупреждениях импорта;
  результаты могут отличаться от контрольных чисел Excel.

## Работа менеджера

1. Скачать шаблон и заменить синтетические примеры своими данными.
2. Загрузить файлы, подтвердить обезличивание клиентских данных.
3. Проверить количество строк, выбранный склад, предупреждения и preview.
4. Нажать расчёт. Вход проходит тот же workflow и тот же AI-fallback, что demo.
5. Просмотреть таблицу, группировку по поставщикам и причины.
6. Изменить остатки, пересчитать; после проверки экспортировать CSV/XLSX.

Ошибки формата/валидации отклоняют весь импорт: частичный dataset не публикуется.
Лимиты: 12 файлов, 10 MiB на файл, 30 MiB всего, 50000 строк суммарно,
50 страниц PDF, 100000 дней stockout суммарно до разворачивания периодов.
Нормализованные источники и метаданные сохраняются для аудита; оригинальные
загруженные документы не публикуются и в OpenAI не отправляются.
LLM не восстанавливает пропуски и не извлекает количества из сканов.

## 1С

В 1С сформируйте выгрузки по таблице полей выше, в том числе материальную
ведомость с конечным остатком. Сохраните XLSX/CSV и загрузите их в интерфейсе.
Выходной CSV/XLSX содержит строки рекомендованного заказа; загрузка этих строк
в документ конкретной 1С требует её обработки импорта и проверки менеджером.
Универсальная запись/проведение заказов в неизвестной конфигурации не заявляется.

1С поддерживает опубликованный REST/OData-интерфейс:
https://v8.1c.ru/platforma/rest-interfeys/
Для следующего этапа нужны конфигурация/версия, read-only публикация и образец
реальной ведомости. Секреты передаются через серверное окружение.

PDF-парсер извлекает текстовые таблицы, но не делает OCR:
https://github.com/jsvine/pdfplumber
