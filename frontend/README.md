# Рабочее место закупок Электрокомплект

Одностраничный frontend для HackAlem AI: React, strict TypeScript, Tailwind CSS и Recharts.
Дизайн: графитовая шапка, нейтральные поверхности, тёмно-зелёные действия.

## Запуск
```sh
cd frontend
npm install
npm run dev
```

Проверка и production:
```sh
npm run test
npm run build
npm run preview
```

При ограничениях Windows sandbox на dev-сервер используйте production preview.
Все настройки находятся в frontend; корневая конфигурация не изменяется.

## Готовые сценарии
- KPI по текущим фильтрам; метры и штуки считаются отдельно.
- Поиск, поставщик, категория, риск, только к заказу и фильтр коррекций через KPI.
- Приоритет дефицита с отсутствующим остатком, сортировка и группировка по поставщику.
- Закреплённые заголовки/товар; мобильные карточки; сохранение выбора за пределами фильтра.
- Боковая карточка: количество, причина, известные слагаемые формулы, аномалии и stockout.
- What-if: редактирование остатка/товара в пути, валидация, сброс, черновик на время сессии страницы.
- Проверка выбранного заказа по поставщикам, явное подтверждение локальной выгрузки CSV.
- Аналитика по видимым позициям; горизонтальное сравнение запаса и заказа по отдельным единицам.
- Вкладка данных, свёрнутый Agent Run, loading/error/empty/success и предупреждение о демо-срезе.
- Escape, фокус внутри native dialog и возврат фокуса, skip link, reduced motion.

## Граница API
На момент разработки docs/API_CONTRACT.md пуст. src/types/api.ts не содержит придуманных полей.
src/types/demo.ts и src/mocks/demo.json описывают только визуальный пример из пяти позиций.
Это НЕ контрактный mock. Все загрузки проходят через src/api/client.ts; fixture валидируется при загрузке.
VITE_API_MODE=mock — демо по умолчанию. Другой режим показывает явную ошибку без скрытого fallback.

Не реализованы и не имитируются:
- POST /api/v1/recalculate и реальный what-if результат;
- прогноз спроса, сезонность, рост, дни покрытия и численная компенсация;
- выполнение агента/длительность его этапов;
- утверждение в учётной системе или отправка поставщику.

Черновик what-if не изменяет recommended, KPI или экспорт. Он хранится в React-состоянии до перезагрузки.
Все численные рекомендации остаются исходными. Backend-алгоритм не дублируется.
График сравнения — текущий запас и готовый заказ, а не прогноз или доказательство снижения риска.
Неполученные данные обозначаются «Нет данных», а не нулями.

## Что применено из UX рекомендаций
1. Последовательность риск → рекомендация → объяснение → сценарий → проверка и экспорт.
2. Постепенное раскрытие: drawer товара, свёрнутые технические параметры и Agent Run.
3. Сетка 4/8/12/16/24/32 px, тонкие границы, радиусы 6–8 px, отсутствие декоративной анимации.
4. Видимые базовые фильтры, sticky таблица, выравнивание чисел справа, tabular-nums и единицы.
5. Статус обозначен текстом и иконкой; цвет не единственный сигнал.
6. Мобильные карточки, фокус/клавиатура, явные ошибки, подтверждение перед выгрузкой.
7. Горизонтальные столбцы для сравнения, небольшое число сегментов donut, единицы не смешиваются.

Отклонения осознанные: зелёный акцент взят из референса пользователя вместо синего;
системный Segoe UI используется без внешнего шрифтового запроса; нерабочие разделы и
фиктивные параметры не показаны. Интерфейс не заявляет соответствие WCAG без полного аудита.
